# 生产级在线部署指南

本部署方案面向真实在线体验：后端连接持久化 MySQL 和 Redis Stack，RAG 向量索引、模型缓存与上传文件写入持久磁盘。SQLite 和内存 Checkpoint 只用于本地开发与测试。

## 1. 云端依赖

Render 托管应用进程；数据库与 Redis 需要是云端可访问的服务。项目当前使用 MySQL 和 LangGraph Redis Checkpoint，Redis 服务必须兼容 Redis Stack 搜索索引。

- `mysql_url`：可公网或同 VPC 访问的 MySQL 连接串。不要填写 `localhost` 或 `127.0.0.1`。
- `REDIS_URL`：托管 Redis Stack 连接串。不要填写本地 Redis 地址。
- `LLM_API_KEY`：模型服务密钥。
- `CORS_ORIGINS`：Render 前端服务的完整 HTTPS 域名。
- 前端 `VITE_API_BASE_URL`：后端 HTTPS 域名加 `/api`。

当前 `backend/.env` 中未配置 `mysql_url`；本地 Redis 指向 `127.0.0.1`。这两个值不能直接用于 Render。若已有 MySQL 是本机或 Docker 中的数据库，需要迁移到托管 MySQL，或使用已有的云端数据库地址；不要为了部署把本机数据库端口直接暴露到公网。

## 2. Render Blueprint

根目录 `render.yaml` 定义了：

- 后端 `lab-agent-backend`：常驻付费实例，生产模式启动；需要外部 MySQL、Redis Stack 和模型 API Key。
- 后端持久磁盘 `/var/data`：保存 Chroma 向量库、Embedding 模型缓存和上传文件。
- 前端 `lab-agent-frontend`：静态站点。

后端计划和持久磁盘会产生平台费用。免费 Web Service 会休眠且不能挂载持久磁盘，因此不满足该配置的在线运行要求。部署前在 Render Blueprint 的环境变量输入界面填写 `sync: false` 的变量；`JWT_SECRT_KEY` 由 Render 自动生成。

## 3. 数据库初始化与数据迁移

首次部署前，先在托管 MySQL 建立独立数据库和最小权限账户。把本地必要的实验室、设备和体验账号数据迁移到云端数据库；不要导入真实个人敏感数据作为公开 Demo 数据。

当前后端启动时会执行 SQLAlchemy `create_all`，可创建缺失表，但这不是版本化数据库迁移方案。多人协作和后续迭代前，应补充 Alembic 迁移、备份恢复演练和回滚策略。

## 4. 配置 Render

1. 将 GitHub 仓库 `xuxuefu1-alt/lab-agent` 的 `master` 分支导入 Render Blueprint。
2. 核对后端计划、持久磁盘和前端静态站点；确认预算后再 Apply。
3. 在后端服务填入 `mysql_url`、`REDIS_URL`、`LLM_API_KEY` 和 `CORS_ORIGINS`。
4. `CORS_ORIGINS` 填前端站点域名，例如 `https://lab-agent-frontend.onrender.com`。
5. 在前端服务填入 `VITE_API_BASE_URL=https://<后端域名>/api` 并触发构建。
6. 部署成功后检查 `https://<后端域名>/healthz`，再进入前端验证业务。

密钥和连接串只填 Render 环境变量，不提交 Git，不粘贴到日志或公开文档。

## 5. 本地开发与容器验证

本地联调使用 Docker Compose 中的 MySQL 和 Redis Stack。当前本机 `.env` 中的 MySQL 和 Redis 地址均指向 `127.0.0.1`，只在本机可达，不能填入 Render：

```powershell
$env:LLM_API_KEY = "你的模型密钥"
docker compose -f docker-compose.demo.yml up --build
```

访问 `http://localhost:8080`。本地 Compose 数据卷与云端数据库相互独立。

## 6. 生产验收

- [ ] 后端 `/healthz` 返回 200，数据库和 Redis Stack 可用。
- [ ] 注册、登录、用户与资源查询通过。
- [ ] 创建预约、查询预约、取消预约和确认流程通过。
- [ ] “查询并取消”等多意图请求完成端到端验证。
- [ ] RAG 首次索引后重启服务，向量数据仍存在。
- [ ] 上传文件、会话记忆、Checkpoint 和审计记录符合保留策略。
- [ ] CORS 只允许正式前端域名。
- [ ] 托管 MySQL 已启用备份；完成恢复验证。
- [ ] 完成失败告警、日志和追踪检查。

## 7. 持续交付

```text
feature 分支 -> pytest 与前端构建 -> Pull Request -> GitHub Actions
  -> 合并 master -> Render 自动部署 -> 健康检查与核心业务冒烟测试
```

当前持久磁盘适用于单实例体验环境；它不是多实例共享存储。需要横向扩展时，应将 Chroma 本地持久化替换为托管向量数据库，并为上传文件迁移到对象存储。
