# SSE 流式运行协议

## 目标

让前端能逐步展示 Agent 的阶段、文本和结构化结果，同时让服务端具备有界并发、超时、取消、错误归类和可追踪运行 ID。SSE 只是传输方式，不能改变业务事务和确认语义。

## 当前实现与问题

- `backend/app/api/ai.py` 通过后台线程运行 `chat_llm()`，线程与无界 `queue.Queue` 按请求创建。
- 事件包含进度、delta、final 或 error；`run_id` 和单连接内 `sequence` 已有初步实现。
- 一般 LangGraph 工具调用的开始/成功/失败没有完整的独立事件，工具结果主要随 final 返回。
- 部分确定性文本通过固定字符切片制造逐步输出，不是真正的模型 token 流。
- 客户端断开、服务端请求超时、用户级并发和任务取消需要明确处理。
- 错误事件不能把底层 `str(exc)` 原样返回给用户。

## 事件协议

每个事件均包含：

```json
{
  "protocol_version": 1,
  "run_id": "server-generated-id",
  "sequence": 3,
  "type": "tool.completed",
  "timestamp": "...",
  "data": {}
}
```

建议事件：

- `run.started`：运行 ID、会话 ID、可展示模式。
- `phase.started` / `phase.completed`：理解请求、检索、校验等用户可理解阶段。
- `tool.started`：工具显示名和安全摘要，不发送敏感原始参数。
- `tool.completed`：安全的结果摘要、数据块引用和耗时。
- `tool.failed`：稳定错误码、是否可重试和用户可读提示。
- `delta`：增量文本。
- `final`：完整正文、结构化 blocks、会话 ID、确认状态。
- `run.completed` / `run.failed`：终态事件。
- `heartbeat`：长连接期间保活，不代表业务进度。

终态事件只能有一个；事件序号单调增加。客户端应能忽略重复序号或未知的可选事件类型，并在流结束前未收到终态时展示连接中断状态。

## 服务端运行方式

- 优先采用可取消的异步/任务执行模式，不为每个请求无上限创建线程。
- 给并发槽位、事件缓冲、模型调用、数据库和总运行时长设置上限。
- 监听客户端断连并取消尚未开始提交的计算任务；已提交的写入通过幂等记录查询最终结果，不能因连接中断重复执行。
- 流式传输期间定期发送 heartbeat；反向代理关闭缓冲并配置合理空闲超时。
- event queue 应有界；消费者过慢时按策略阻塞、取消或丢弃非关键进度，不得无限增长。
- 每个运行统一携带 run ID 到模型、工具、审计、日志和 Trace。

## 工具事件和隐私

- 只展示用户理解流程所需的工具名称与状态，不输出内部 Tool schema、系统提示词、密钥或完整敏感查询参数。
- 权限失败、业务冲突、模型超时、知识库故障和内部错误映射到稳定事件错误码。
- 发生网络断开时，用户可查询运行结果或重试；写操作以幂等键避免重复。
- 工具结果 blocks 只在 final 或专用结构化事件中返回一次，不重复渲染 checkpoint 中的旧结果。

## 前端消费契约

- 使用增量 UTF-8 解码，按 SSE 空行边界解析事件；支持 CRLF、多行 data 和分片 JSON。
- 收到 `run.started` 后创建运行状态；收到 `delta` 更新文本；收到 `tool.*` 更新阶段；收到 `final` 渲染 blocks 和确认状态。
- `run.failed` 清理未完成的临时消息，保留可重试提示和 run ID。
- 页面切换/用户取消时中止 fetch；若写操作已提交，随后通过幂等状态查询最终结果。
- 对重复、乱序、断流和过期连接有明确行为，不把半截文本当作最终答案。

## 实施步骤与验收

- [ ] 定义版本化事件 schema 和终态规则。
- [ ] 给工具执行增加启动、完成和失败回调。
- [ ] 将线程/队列执行替换为有界且可取消的运行机制。
- [ ] 增加 heartbeat、超时、断连处理和安全错误映射。
- [ ] 更新前端 SSE parser 和运行状态显示。
- [ ] 覆盖慢客户端、客户端断开、模型超时、工具失败、重复事件和写入后断连场景。

**验收条件：**高并发下资源有上限；连接断开不会导致后台无限运行；单次运行有唯一可关联 ID；工具状态能正确显示；写入结果可查询且重试不会重复执行。
