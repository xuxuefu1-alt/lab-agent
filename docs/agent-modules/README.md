# Agent 模块改造文档

这组文档把 `lag-agent` 的 Agent 改造拆成五个独立模块。每份文档说明当前实现、目标边界、接口契约、实施步骤和验收条件，后续可以按模块逐个改造。

## 推荐顺序

1. [意图路由与参数理解](intent-routing.md)：先统一系统如何理解用户本轮请求。
   - [意图识别评估测试集](意图识别评估测试集.md)：按意图、语气、槽位和工作流续接回放路由结果。
2. [工具执行与授权边界](tool-execution.md)：让每个业务动作都有明确的服务端策略和结果契约。
3. [会话记忆与工作流状态](memory-state.md)：定义对话历史、预约草稿和 LangGraph checkpoint 的事实来源。
4. [RAG 知识服务](rag-knowledge.md)：建立文档版本、检索、引用和评测闭环。
5. [SSE 流式运行协议](sse-streaming.md)：最后稳定前后端事件协议、取消和并发行为。

意图路由与工具契约是主链路；记忆、RAG、SSE 分别依赖清楚的身份、状态和运行结果契约。RAG 可在工具模块改造期间并行准备文档与评测集。

## 通用原则

- 模型负责理解语言、抽取候选信息和解释结果；服务端负责授权、业务规则、状态转移和写库。
- 结构化输入必须经过 schema 校验；模型输出、会话摘要、检索内容和工具结果均不能作为权限来源。
- 写操作使用预览、明确确认、服务端重验、事务和幂等保护。
- 每次改造先补回归样例，再替换实现；保留失败案例，避免关键词补丁不断回归。
- 不以“模型自报置信度”作为安全条件；不确定时走澄清路径。
