# RAG 知识服务

## 目标

把实验室规则、开放时间和使用手册变成可版本化、可控权限、可定位引用、可评测的新鲜知识服务。实时预约状态必须查询业务数据库，不能从 RAG 文档推断。

## 当前实现与边界

- `backend/app/services/kb_services.py` 使用本地持久化 Chroma 和本地 SentenceTransformer embedding。
- 当前按整个 Markdown 文件创建向量；只有 collection 为空时才导入文件。
- 检索使用固定数量、固定距离转换阈值并截取前两篇；没有基于标注集评估阈值。
- 返回内容只带文件名，没有文档版本、段落锚点、有效日期或引用 ID。
- 当前知识文件是本地静态 Markdown；文件上传接口没有完成安全入库和发布流程。

因此，当前 RAG 可用于单实例原型和小型静态文档试验，不能保证生产知识的更新及时性、权限隔离和可追溯性。

## 文档与 Chunk 契约

文档元数据至少包括：

```text
document_id, version, title, source, content_hash
status: draft | reviewing | published | archived
access_scope, owner, approved_by
effective_at, expires_at, updated_at
```

Chunk 元数据至少包括：

```text
chunk_id, document_id, document_version
section_title, page_or_anchor, sequence
embedding_model, content_hash, access_scope
```

Chunk 按标题和语义段落切分，保留上下文标题；过短片段合并，超长段落再切分。chunk 大小和重叠由知识评测集调优，不把某个固定字符数当成通用最佳值。

## 入库与发布流程

```text
上传/同步
  -> 文件大小、真实类型、安全扫描
  -> 解析与结构校验
  -> 去重与版本识别
  -> 按标题/段落切片
  -> embedding 与索引构建
  -> 抽样质量检查
  -> 审核发布
  -> 原子切换有效版本
```

- 草稿和未审核文档不能参与线上检索。
- 文档更新应生成新版本，构建完毕后原子切换，失败时保留上一有效版本。
- 支持按 document ID 重建、撤回、归档和回滚。
- 记录入库状态、错误、用时、chunk 数和 embedding 模型版本。

## 查询流程

1. 根据认证上下文确定用户可见的 `access_scope`，先过滤权限和有效期，再检索。
2. 对政策问答使用向量检索；如果文档标题、日期或编号适合关键词精确匹配，可增加关键词检索并融合排序。
3. 返回 top-k 候选和检索元数据；重排器是否需要由离线评测决定。
4. 使用验证集选择拒答阈值；低于阈值、结果冲突或文档过期时明确回答“没有足够依据”。
5. 生成回答时携带引用 ID；响应结构保留来源文档、版本、章节和可展示片段。
6. 对实时开放、设备维护、预约冲突和用户预约状态调用业务服务，不用知识库代替实时数据。

建议结果契约：

```json
{
  "answer": "...",
  "citations": [
    {
      "document_id": "booking-rules",
      "version": 4,
      "title": "预约规则",
      "section": "预约时段",
      "chunk_id": "..."
    }
  ],
  "evidence_status": "supported | insufficient | conflicting"
}
```

## 提示注入与数据隔离

- 检索内容永远是数据，不是指令；与系统提示和工具结果分区传递。
- 文档中要求泄密、改权限或调用工具的文本不得改变工具可用范围。
- 不向模型提供用户无权访问的 chunk；不能只依赖生成后过滤引用。
- RAG 工具只负责检索，不负责修改知识库或直接执行预约。

## 评测

建立版本化问答集，至少覆盖正常问答、同义问题、无答案、文档冲突、过期文档、权限隔离和提示注入。跟踪：

- 检索召回：Recall@k / MRR 或与业务目标匹配的排序指标。
- 答案事实性和引用正确率：引用是否支持对应结论。
- 拒答行为：没有依据时是否避免编造。
- 更新时效：新版本发布和旧版本撤回后的检索表现。
- 不同文档类型、用户权限和查询意图的分组表现。

阈值和发布门槛由语料评测结果确定；不要将 `1 / (1 + distance)` 直接解释为事实准确率。

## 实施步骤与验收

- [ ] 定义文档、版本、chunk 和引用 schema。
- [ ] 构建可重复运行的离线索引器和增量同步任务。
- [ ] 建立审核、发布、撤回、重建和回滚流程。
- [ ] 让检索接口返回候选 chunk 与引用元数据。
- [ ] 构建标注问题集，比较当前检索与 chunk/混合检索方案。
- [ ] 为发布流程添加权限过滤、无证据拒答、旧版本撤回和失败回滚测试。

**验收条件：**文档版本可追溯；更新/撤回在约定时限内生效；引用可落到章节；越权内容不会进入模型上下文；无证据时不会将 RAG 结果包装成事实。
