# AI Agent Badcase 记录

> 目的：记录实验室管理 AI 助手在开发、联调和上线前验证中发现的问题，明确根因、处理方式和回归要求。新增问题必须补充到本文档，不以临时口头说明代替。

## 使用规则

- 每个 badcase 必须包含：用户输入、错误表现、根因、修复策略、验证方式和当前状态。
- 涉及权限、预约写入、取消预约、确认 token 的问题，必须增加服务端测试，不能只验证模型回复。
- 涉及 LangGraph checkpoint 的问题，必须区分“模型上下文”和“本轮响应输出”。
- 任何历史工具结果都不能因为 checkpoint 恢复而再次渲染到当前回复。

## BC-001 设备接口 500

**用户表现**：`POST /api/equipment` 返回 500，ASGI 日志出现数据库异常。

**根因**：数据库查询或事务异常后没有统一回滚，异常继续向 FastAPI 冒泡；错误信息也没有形成稳定的业务错误响应。

**处理策略**：

- AI Tool 数据库异常统一执行 `rollback()`。
- API 层统一异常处理，返回可识别的错误码和用户提示。
- 结构化记录请求路径、用户、异常类型和 trace 信息，不记录密码、token 等敏感数据。

**验证**：接口异常、数据库连接中断、工具失败后下一次请求仍可正常执行。

**状态**：已处理，仍需持续观察生产日志。

## BC-002 预约信息分多轮发送后重复询问

**用户输入**：

```text
我要预约
广州化学实验室
明天下午4点到6点
```

**错误表现**：每一轮都重复询问实验室或日期时间，无法进入预约确认。

**根因**：预约流程只解析当前消息，没有将多轮字段合并到结构化状态；早期版本还把空草稿误判成没有活动流程。

**处理策略**：

- 使用 LangGraph booking 子图。
- 使用 Redis Stack Checkpointer 保存预约草稿。
- 草稿绑定 `user_id + conversation_id + workflow`。
- 增加 `workflow_active`，空草稿也能保持预约流程活动状态。
- 当前消息只覆盖当前字段，未提供的字段从 checkpoint 恢复。

**验证**：内存 checkpoint 和 Redis Stack 均验证三轮预约续接。

**状态**：已处理。

## BC-003 “继续前面的预约”落到普通聊天

**用户输入**：`继续前面的预约`。

**错误表现**：AI 返回与预约无关的普通回答。

**根因**：恢复指令不包含实验室、日期或时间字段，没有命中预约字段解析器，随后被普通聊天图接管。

**处理策略**：

- 增加预约恢复意图识别：`继续预约`、`接着预约`、`恢复预约` 等。
- 有活动 booking checkpoint 时强制进入预约子图。
- 无活动预约流程时明确提示重新开始，不交给普通模型自由发挥。

**验证**：已有 checkpoint 时恢复缺失字段或重新展示确认；无 checkpoint 时返回明确提示。

**状态**：已处理。

## BC-004 取消预约无法通过 AI 执行

**用户输入**：`帮我取消我的预约`。

**错误表现**：AI 只能查询预约，不能完成取消。

**根因**：后端普通预约页面已有取消接口，但 AI Tool 层没有取消准备工具、确认 token 和取消工作流。

**处理策略**：

- 增加 `prepare_cancel_booking`。
- 取消必须先展示确认信息，再由服务端执行写入。
- token 绑定用户、会话、预约和过期时间，并保存 hash。
- 服务端再次校验预约归属、状态和权限。
- 使用 Redis 幂等锁和数据库行锁，避免重复取消。

**验证**：本人取消、跨用户取消、重复确认、过期 token、已取消预约。

**状态**：已处理。

## BC-005 实验室简称无法识别

**用户输入**：`我要预约广州实验室，明天下午4点到6点`。

**错误表现**：数据库存在“广州化学实验室”，但 AI 提示无法识别实验室。

**根因**：早期只支持完整名称包含匹配，不支持位置、简称和候选评分。

**处理策略**：

- 完整名称优先。
- 实验室名称去除通用后缀后匹配。
- 支持位置匹配和轻度模糊匹配。
- 唯一候选自动选择，多候选必须让用户选择，禁止猜测。

**验证**：唯一简称、多候选同地点、停用实验室和无匹配结果。

**状态**：已处理。

## BC-006 结构化卡片重复或正文过长

**用户表现**：卡片已经展示详情，正文又重复表格或出现“详情已按卡片展示”等内部说明。

**根因**：工具结果和模型正文同时承担展示职责，摘要函数没有严格限制输出内容。

**处理策略**：

- 卡片负责详细数据展示。
- 正文只保留一句事实摘要。
- 不向用户暴露“生成卡片”“工作流”等内部实现术语。

**状态**：已处理，需继续做前端视觉回归。

## BC-007 checkpoint 历史工具结果污染当前回复

**用户输入**：`帮我看下有哪些实验室开放`。

**错误表现**：

```text
当前有 2 间开放实验室。
已查询到 5 个用户。
当前有 4 间开放实验室。
```

**根因**：LangGraph checkpoint 保留完整历史是正确的，但响应渲染遍历了整个 checkpoint 的 `ToolMessage`，没有只读取本轮新产生的工具结果。

**处理策略**：

- 调用图前读取 checkpoint 中已有消息数量。
- 调用图后只处理本轮新增消息范围。
- 卡片聚合和正文摘要只基于本轮工具结果。
- 历史结果只用于模型理解，禁止再次渲染。

**验证**：先查询用户，再查询实验室；当前实验室查询不能出现用户卡片或旧实验室数量。

**状态**：已修复，待真实页面回归。

## BC-008 上下文与业务权限混淆

**错误表现**：用户消息或知识库文本试图声明管理员权限、修改规则或调用内部工具。

**根因**：把自然语言上下文当成可信权限来源。

**处理策略**：

- 用户身份、角色和资源归属只由服务端提供。
- Tool 层做最终权限校验。
- 知识库和工具返回值视为不可信数据。
- 写操作必须经过显式确认和服务端二次校验。

**状态**：已处理，需持续扩充对抗性测试。

## 回归清单

- [ ] 单轮实验室查询只返回当前实验室结果。
- [ ] 多轮预约字段可以跨消息合并。
- [ ] “继续前面的预约”可以恢复活动预约流程。
- [ ] 无活动预约流程时恢复指令不会进入普通聊天。
- [ ] 取消预约必须确认，且不能跨用户操作。
- [ ] 历史工具结果不会污染当前卡片。
- [ ] checkpoint 过期、Redis 不可用、数据库异常都有明确失败路径。
- [ ] 生产环境使用 Redis Stack，不使用普通 Redis 作为 LangGraph checkpoint。
